# حالت‌های حافظه مدل در LlamaForge

از مسیر **Settings → Model memory mode** یکی از سه حالت را انتخاب کنید و **Save settings** را بزنید. انتخاب در بارگذاری بعدی مدل اعمال می‌شود.

## 1) RAM Only
- هدف: وزن‌های مدل در RAM بمانند و به swap/pagefile رانده نشوند.
- پیاده‌سازی: `--load-mode mlock` و `--lazy-mode off` در Runtimeهای جدید llama.cpp.
- قبل از اجرا، LlamaForge بررسی می‌کند که مدل + سربار Runtime داخل سقف امن RAM جا شود. اگر جا نشود اجرا را متوقف می‌کند.
- مناسب برای بیشترین سرعت زمانی که مدل واقعاً در RAM جا می‌شود.

## 2) SSD Test
- هدف: تست بدترین/دیسک‌محورترین حالت عملی بدون preload سنگین مدل.
- پیاده‌سازی: `--load-mode mmap` + `--lazy-mode on` + `--no-warmup` در Runtimeهای سازگار.
- صفر RAM ممکن نیست: KV cache، بافرهای محاسباتی و مقداری page cache ویندوز همچنان RAM مصرف می‌کنند.
- مناسب برای آزمایش اینکه مدل بزرگ‌تر از RAM روی SSD چه رفتاری دارد. سرعت می‌تواند بسیار پایین باشد.

## 3) Hybrid Smart
- هدف: تا جای ممکن صفحات داغ مدل در RAM بمانند و صفحات سرد از فایل GGUF روی SSD تأمین شوند.
- پیاده‌سازی: `mmap` و page cache سیستم‌عامل. LlamaForge سقف RAM انتخابی را در برنامه‌ریزی لحاظ می‌کند.
- مناسب‌ترین حالت برای مدل‌هایی که کمی یا مقدار قابل‌توجهی از RAM بزرگ‌ترند.

## آیا می‌شود بر اساس سؤال فقط «قسمت مربوط» از مدل را لود کرد؟
برای مدل‌های Transformer متراکم (Dense)، نه به آن شکلی که مثلاً سؤال را تحلیل کنیم و فقط چند گیگ مرتبط را انتخاب کنیم؛ تقریباً همه لایه‌های مدل برای تولید هر توکن در مسیر محاسبه شرکت می‌کنند. `mmap` می‌تواند صفحات موردنیاز را هنگام دسترسی از SSD بیاورد، ولی نمی‌تواند معنای سؤال را به یک بخش مستقل از وزن‌های مدل نگاشت کند.

در مدل‌های Mixture-of-Experts خود مدل برای هر توکن تعدادی expert را انتخاب می‌کند، اما این انتخاب داخل inference انجام می‌شود و معادل «قبل از اجرا حدس بزن کدام فایل/بخش مدل برای این سؤال لازم است» نیست.
