# اصلاح فرم Telegram در 0.34.4-telegram-ui

مشکل گزارش‌شده در کد بازتولید شد. اصلاح قبلی تیک‌های Permission، متن فرم Telegram را پوشش نداده بود. علاوه بر پاک‌شدن فیلدها، یک پاسخ دیرهنگام وضعیت می‌توانست پس از شروع تایپ، همان ورودی را از DOM حذف کند و فوکوس را بگیرد.

## تغییرات

| مشکل | اصلاح |
|---|---|
| تایپ هم‌زمان با پاسخ دیرهنگام وضعیت | پس از دریافت پاسخ دوباره فوکوس بررسی می‌شود؛ ورودی فعال تعویض نمی‌شود |
| پاک‌شدن شماره/API ID/Hash/کد/رمز با Refresh داخلی، ذخیرهٔ دسترسی یا برگشت به Agent | Draft فرم فقط در حافظهٔ همان تب نگه‌داری می‌شود؛ Autofill بدون رویداد input نیز پیش از بازسازی حفظ می‌شود |
| پایان Login پس از رفتن به صفحهٔ دیگر | نتیجه در وضعیت فرم نگه‌داری می‌شود؛ callback دیگر به فیلد حذف‌شده دست نمی‌زند و مرحلهٔ بعد هنگام برگشت نمایش داده می‌شود |
| دکمهٔ فعال با درخواست در حال اجرا و نبود بازخورد روشن | وضعیت Working و غیرفعال‌شدن کنترل‌های متعارض؛ جلوگیری از فراخوانی تکراری؛ آزادشدن دکمه‌ها پس از خطا |
| گم‌شدن پیام ورود دومرحله‌ای یا خطا با Refresh | مرحلهٔ code/password و پیام وضعیت مستقل از DOM نگه‌داری می‌شوند |
| `Number('۱۲۳')` مقدار معتبر تولید نمی‌کرد | تبدیل ارقام فارسی/عربیِ API ID، شماره و کد به ارقام ASCII پیش از ارسال؛ متن رمز بدون تغییر می‌ماند |
| ارسال فیلد خالی و خطای نامفهوم backend | اعتبارسنجی محلی شناسه، Hash، شماره با کد کشور و کد ورود |
| سربرگ حساب پس از Resume/Disconnect به‌روز نمی‌شد | نام/وضعیت حساب، کنترل‌ها و نصب به‌صورت درجا به‌روز می‌شوند |
| پاسخ قدیمی وضعیت، نتیجهٔ ورود جدید را برمی‌گرداند | پاسخ‌های قدیمی Agent و Snapshot شروع‌شده پیش از تغییر ورود، وضعیت جدید Telegram را بازنویسی نمی‌کنند |

دکمه‌های ورود و ذخیرهٔ Permission قفل جدا دارند؛ درخواست Telegram بی‌دلیل Save تنظیمات را مسدود نمی‌کند. نصب Telegram تا وقتی صفحهٔ Agent باز است وضعیت را پیگیری می‌کند. برچسب‌ها به ورودی خود متصل و فیلدهای شناسه/شماره/کد چپ‌به‌راست شدند.

## تست و شواهد

- Baseline نسخهٔ 0.34.3: **420 passed, 1 skipped** در 46.20 ثانیه.
- ۱۲ تست جدید Node در `tests/test_workspace_ui.cjs`؛ Fixture جدید هنگام بازسازی صفحه، Nodeهای قدیمی را واقعاً از مجموعهٔ شبیه‌سازی‌شده خارج می‌کند، به‌جای اینکه همیشه همان ورودی قبلی را برگرداند.
- اجرای اولیهٔ هفت سناریوی گزارش‌شده: **7 failed, 18 passed**. دو سناریوی تکمیلیِ نمایش حساب و Autofill نیز پیش از اصلاح شکست خوردند.
- نتیجهٔ نهایی UI و پروتکل: **31 passed**، شامل ۳۰ مورد UI و یک فایل پروتکل. مسیر Login با کد و 2FA، خطا، کلیک تکراری، Resume، Disconnect، تأیید/لغو Revoke، نصب، Refresh و پاسخ دیرهنگام پوشش دارند.
- Suite نهایی پروژه: **420 passed, 1 skipped** در 46.74 ثانیه. تست‌های Node داخل دو wrapper موجود pytest هم اجرا می‌شوند؛ افزودن موردهای Node تعداد caseهای pytest را افزایش نمی‌دهد.
- Syntax رابط محلی و Bridge و `git diff --check` موفق‌اند. PHP CLI در محیط نصب نیست؛ همان تست محیطی اجرا نشده است.

شواهد مصنوعی: `audit/telegram-ui-baseline.txt`، `telegram-ui-red.txt`، `telegram-ui-followup-red.txt`، `telegram-ui-final.txt` و `telegram-ui-suite-final.txt`.

آزمون‌ها با DOM و پاسخ API کنترل‌شده اجرا شدند؛ Chromium اجرایی در محیط حاضر نبود. بررسی بصری مرورگر Windows و ورود واقعی به حساب Telegram انجام نشده‌اند. این تست‌ها صحت رفتار فرم را بررسی می‌کنند، نه تحویل کد از سرویس Telegram یا Vault سیستم کاربر.

## نصب و رفتار فرم

1. LlamaForge قبلی را کامل ببندید و بستهٔ **0.34.4-telegram-ui** را در پوشهٔ جدا باز کنید؛ سپس `llamaforge/run.bat` را اجرا کنید.
2. رابط محلی را Reload کنید و در Agent کارت Telegram را باز کنید. شماره را همراه کد کشور مانند `+989123456789` وارد کنید. ارقام فارسی و انگلیسی هر دو پذیرفته می‌شوند.
3. اگر وابستگی آماده نیست، ابتدا Install Telegram support را بزنید. شماره و اطلاعاتی که وارد کرده‌اید با پیشرفت نصب پاک نمی‌شوند.
4. Send login code و سپس Verify login را بزنید؛ در صورت درخواست رمز دومرحله‌ای، همان دکمه مرحلهٔ رمز را تأیید می‌کند.

Refresh **داخلی** برنامه و رفت‌وبرگشت صفحات، Draft را حفظ می‌کنند. Reload کامل مرورگر یا بستن تب آن را پاک می‌کند. API Hash، کد و رمز در localStorage/sessionStorage ذخیره نمی‌شوند؛ Secretهای مصرف‌شده در مرحلهٔ موفق پاک می‌شوند. ذخیرهٔ Session حساب همچنان در Vault سیستم‌عامل انجام می‌شود.

## محدودهٔ تغییر

منطق فرم در `web/static/app.js` و تست‌های آن تغییر کرده‌اند؛ READMEها، این گزارش و CHANGELOG به‌روز شده‌اند. شمارهٔ نسخه و User-Agentهای برنامه هماهنگ شدند. backend ورود/Permission، پروتکل Bridge، updater، توکن‌ها، مدل، آموزش Brain و Adaptive تغییر رفتاری ندارند. وابستگی جدیدی اضافه نشده است.

Benchmark inference برای تغییر رابط کاربری انجام نشده؛ Prompt tok/s، Generation tok/s، TTFT و RAM مدل در این دور موضوع تغییر نبوده‌اند. اگر در نسخهٔ جدید دکمه خطای اتصال نشان داد، متن همان خطا و شمارهٔ نسخه برای ادامهٔ عیب‌یابی لازم است.
