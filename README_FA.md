# مجموعه LlamaForge Suite

## شتاب‌دهی همزمان CPU + GPU داخلی

نسخهٔ `0.34.0-smart-brain` چهار حالت محاسباتی صریح دارد: **CPU only**، **GPU max offload**، **CPU + GPU Hybrid** و **Max Both**. روی ویندوز گرافیک‌های داخلی AMD/Intel و NVIDIA شناسایی می‌شوند؛ GPU/Hybrid از Runtime رسمی Vulkan در `llama.cpp` استفاده می‌کنند. در Hybrid سهم GPU از ۵ تا ۹۵ درصد قابل تنظیم است و Max Both برای iGPUها سهم GPU را پایین نگه می‌دارد تا CPU هم کار واقعی بیشتری انجام دهد و Context دلخواه مثل 8000/8192 در Settings بدون برگشت خودکار ذخیره می‌شود. دانلود Runtime نیز درصد، حجم، سرعت و ETA را نمایش می‌دهد.

در Task Manager معمولاً باید هم CPU و هم GPU فعالیت داشته باشند. بسته به درایور، بار Vulkan ممکن است در نمودار `Compute` به‌جای `3D` واضح‌تر دیده شود.

این مخزن دو بخش اصلی را در یک پروژه نگه می‌دارد:

- `llamaforge/`: اجرای مدل محلی GGUF، Agent، Skills، کنترل Context و Sampling، Load/Reload/Unload مدل و اتصال به سایت‌ها.
- `web-bridge/`: رابط وب PHP شبیه چت، تاریخچهٔ مجزا برای هر مرورگر، نمایش زندهٔ فعالیت Agent، انتخاب مدل، توقف پاسخ و توقف/Unload مدل.

## Smart Skill Tree v4

در نسخهٔ 0.30، Skillها از حالت «یک ابزار برای هر سؤال» خارج شده‌اند. Router ابتدا بین قابلیت‌های عمومی **Live Web، Time & Calendar، Files & Attachments، Browser، API و Extensions** انتخاب می‌کند و فقط ابزارهای همان شاخه را به مدل نشان می‌دهد. درخواست‌های واضح مثل «امروز چندمه؟» یا فایل پیوست دیگر با پاسخ اشتباه «دسترسی ندارم» به Direct Chat نمی‌افتند.

مجوز تغییرات محلی Calendar/File Manager از مجوز پرریسک نوشتن روی سایت جدا شده است. تغییرات محلی پیش‌فرض روشن‌اند، در حالی که POST/PUT/DELETE و کلیک/تایپ روی سایت‌های خارجی همچنان مجوز مستقل دارند. File Manager همچنین می‌تواند ZIP پروژه را امن بخواند و فایل‌های متنی/کد Workspace را ایجاد یا ویرایش کند.

## نکته امنیتی

تاریخچهٔ مرورگرها از هم جدا شده است، اما این جای سیستم Login/Account را نمی‌گیرد. اگر سایت عمومی و چندکاربره است، باید احراز هویت واقعی هم به Bridge اضافه شود و مالکیت گفتگو به شناسهٔ حساب کاربر متصل شود.

توکن‌ها، `data/config.php`، مدل‌های GGUF و فایل‌های Runtime داخل Git ذخیره نمی‌شوند.

برای نصب Bridge ابتدا `web-bridge/START-HERE.txt` را بخوانید.


## مسیریابی هوشمند Skill

برای سلام‌های کاملاً روشن مسیر مستقیم کم‌هزینه وجود دارد؛ در درخواست‌های دیگر مدل محلی ابتدا خودش بین **پاسخ مستقیم** و **Skills** انتخاب می‌کند. اگر Skill لازم باشد، در مرحلهٔ بعد خانوادهٔ Web / API / Browser / Connector / Custom را انتخاب می‌کند؛ سپس فقط ابزارهای همان شاخه به مرحلهٔ انتخاب Action می‌روند. خروجی واقعی Skill دوباره به مدل برمی‌گردد تا بر اساس Observation تصمیم بعدی را بگیرد. بنابراین پیام‌هایی مثل سلام، نوشتن متن و توضیح مفهومی وارد Skill loop نمی‌شوند، ولی درخواست واقعی برای بازکردن سایت، جست‌وجوی وب، HTTP/API یا تعامل مرورگر می‌تواند وارد شاخهٔ مناسب شود. پاسخ نهایی نیز به زبان کاربر برگردانده می‌شود.

## آپدیت Web Bridge از داخل LlamaForge

Bridge نسخهٔ 3.4 یک Updater احراز هویت‌شده دارد. بعد از این‌که این نسخه یک‌بار روی هاست نصب شد، در Settings برنامهٔ LlamaForge برای سایت متصل دکمه‌های **Update Bridge** و **Rollback** فعال می‌شوند. برنامه ZIP نسخهٔ Bridge همراه خودش را به هاست می‌فرستد، قبل از نصب Backup می‌سازد و در صورت خطای نصب Rollback خودکار انجام می‌دهد. `data/config.php`، توکن‌ها و تاریخچهٔ چت کاربران دست‌نخورده می‌مانند.

**نکتهٔ نصب اول:** Bridge قدیمی که هنوز `bridge-update.php` ندارد نمی‌تواند خودش این قابلیت را ایجاد کند. فقط برای مهاجرت اولیه باید نسخهٔ 3.4 را یک‌بار دستی روی هاست قرار دهید؛ از آن به بعد آپدیت‌ها و Rollback از خود LlamaForge انجام می‌شود.

## تغییرات 0.33.0

حالت **Adaptive AutoTune** اضافه شده است. AutoTune با `llama-bench` همان GGUF و همان Runtime نصب‌شده را روی چند ترکیب Thread CPU، تعداد لایه GPU و Batch/UBatch اندازه‌گیری می‌کند و نتیجه برنده را برای همان فایل مدل ذخیره می‌کند. برای مدل‌های بزرگ، Context و بافرهای Launch بدون تغییر دادن تنظیم ذخیره‌شده کاربر موقتاً کوچک می‌شوند، `parallel=1` می‌ماند و در صورت نیاز mmap استفاده می‌شود تا مدل‌های حدود 10–12GB شانس بیشتری برای اجرا روی سیستم 16GB داشته باشند. mmproj فقط هنگام اولین تصویر Load می‌شود و Skillهای read-only مستقل می‌توانند موازی اجرا شوند، بدون این‌که چند کپی از وزن‌های مدل ساخته شود. Speculative n-gram نیز در Runtimeهای سازگار قابل فعال‌شدن است؛ خود `llama-bench` آن را اندازه‌گیری نمی‌کند.

## تغییرات 0.32.0

این نسخه Streaming واقعی پاسخ نهایی Agent و نسخه وب، دریافت هر نوع فایل با رویکرد Metadata-first، مسیریابی هوشمندتر Skillهای فایل/تقویم، تقویم جمع‌وجورتر و حالت Full RAM با `--load-mode none` را اضافه می‌کند. در Smart RAM اگر مدل در بودجه امن حافظه جا شود، mmap خودکار کنار گذاشته می‌شود.

## نسخهٔ 0.34.0 Smart Skills

دقت و سرعت مسیر اسکیل، قرارداد عملیات، رسید پایدار فایل، خواندن امن آرشیو و Office، استریم و محافظت Adaptive اصلاح شدند. گزارش آزمون و محدودیت‌های واقعی در [گزارش فنی](llamaforge/AUDIT_REPORT_FA.md) آمده است. اسکیل جداگانه برای هر سؤال ساخته نمی‌شود.

بازنویسی آموزش و ارزیابی Brain: [راهنمای فارسی](llamaforge/BRAIN_SYSTEM_FA.md). نتایج آزمون و محدودیت‌های بنچمارک: [گزارش فنی](llamaforge/AUDIT_REPORT_FA.md).

## رابط و تقویم 0.34

رابط محلی: چت خلوت، جستجو/تغییر نام تاریخچه، حفظ پیش‌نویس و فایل‌ها بین گفتگوها، تقویم ماهانه با برنامهٔ روز انتخاب‌شده و فرم ساخت/ویرایش/لغو رویداد شمسی و میلادی. ظاهر Bridge نیز خواناتر شده است؛ منطق توکن و به‌روزرسانی آن تغییر نکرده است. پیش‌نمایش تصویری Windows/mobile هنوز نیازمند بررسی روی دستگاه واقعی است.
